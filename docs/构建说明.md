# 词链 WordWeave：Android 构建说明

本项目使用Android原生Java Activity与本地WebView界面。词库、页面和学习逻辑随APK打包；v1.2.0增加Sherpa-ONNX原生CPU语音运行库、解压及Kotlin等依赖。离线语音模型本体不随APK打包，由用户在应用内按需下载。

## 直接安装

使用本次交付的双ARM通用包`词链_WordWeave_v1.2.0.apk`，或GitHub的[ARM64包](https://github.com/dklk590/-/raw/refs/heads/main/apk/WordWeave-v1.2.0-arm64-v8a.apk)、[ARMv7包](https://github.com/dklk590/-/raw/refs/heads/main/apk/WordWeave-v1.2.0-armeabi-v7a.apk)，允许文件管理器安装未知来源应用后安装。ARM64适合大多数现代手机，ARMv7适合旧款32位ARM手机。当前版本为1.2.0（versionCode 3），最低支持Android 8.0（API26），面向Android 15（API35），没有x86 / x86_64版本。

通用包约43 MB，包含两个ARM架构及未压缩原生库；GitHub分架构包压缩原生库，由Android安装时解压。三种交付包的功能、应用id、版本与签名相同，沿用前一版本的本地调试证书，可覆盖前一版本并保留学习数据；升级前建议先导出备份。

系统TTS与本机模型均可在设置中选择；本机模型需先下载、校验并安装。操作见[发音与模型使用说明](发音与模型使用说明.md)。

## Android Studio

1. 安装 Android Studio，打开本项目根目录。
2. 使用 JDK17；安装 Android SDK Platform35 与 SDK Build Tools35.0.0。
3. 等待 Gradle 同步完成，然后选择 `app` 并运行，或使用 Build APK。
4. 首次同步需要联网获取 Gradle8.9 和 Android Gradle Plugin8.7.3。项目固定了 Gradle 分发文件的 SHA256 校验值。

Linux/macOS：

```sh
./gradlew assembleDebug
```

Windows：

```bat
gradlew.bat assembleDebug
```

标准Gradle产物位于`app/build/outputs/apk/debug/app-debug.apk`。`local.properties`是本机SDK路径文件，由Android Studio自动创建，请勿复制其他电脑的路径。

源码和源码ZIP包含`app/libs/`中的7个固定JAR，以及`app/native/*.so.gz`中的两种ARM原生库压缩副本。Gradle的`preBuild`自动用Java校验压缩文件SHA256，解压后再次校验原生库SHA256，还原到`app/src/main/jniLibs/`再构建。无需另装Python、下载运行库或编译C++；若文件损坏，校验失败会终止构建。

固定依赖为Sherpa-ONNX 1.13.8官方静态CPU JNI、Commons Compress 1.28.0、Codec 1.19.0、IO 2.20.0、Lang 3.18.0、Kotlin 1.9.24和Annotations 13.0。文件清单与哈希在`dependencies.lock.json`，原生库内相关第三方组件也有独立许可，来源与许可保存在`LICENSES/`及APK内`assets/licenses/dependencies/`。

## 使用官方 SDK 直接构建

如果 Gradle 下载不便，可以通过本项目提供的脚本构建。同样需要已安装的 JDK17、SDK Platform35 和 Build Tools35.0.0，脚本不会替用户下载或接受 SDK 许可证。

```sh
python3 scripts/build_sdk.py --sdk /你的/Android/Sdk
```

Windows 将 `python3` 改为 `python`，SDK 路径可使用引号：

```bat
python scripts\build_sdk.py --sdk "C:\Users\你的用户名\AppData\Local\Android\Sdk"
```

脚本先自动调用`scripts/prepare_native.py`，校验并还原源码内的压缩原生库，再执行AAPT2资源编译和链接、包含JAR依赖的Java编译及D8转换，打包ARM原生库，然后zipalign对齐、apksigner签名与校验。默认输出双ARM通用包`app/build/outputs/apk/debug/wordweave-debug.apk`，并打印SHA256。构建时不联网获取运行库；模型仍由安装后的应用下载，构建脚本不下载模型。

如需较小的单架构包：

```sh
python3 scripts/build_sdk.py --sdk /你的/Android/Sdk --abi arm64-v8a --compress-native --output WordWeave-v1.2.0-arm64-v8a.apk
```

32位ARM包将`--abi`改为`armeabi-v7a`，并更改输出文件名。`--compress-native`压缩JNI条目并设置`extractNativeLibs=true`，由Android安装时解压；默认通用包保持JNI未压缩并做16KB条目对齐。架构与压缩方式不改变词库和应用功能，覆盖更新仍需同一签名。

## 调试签名

源码压缩包和 Git 仓库均不附带签名私钥。本次交付的 APK 使用本地保留的旧调试证书；自行构建时，Gradle 优先使用本机的 `signing/debug.keystore`，缺少此文件时使用电脑上的标准调试证书。SDK 脚本在缺少此文件时生成新证书。GitHub Actions 使用运行器生成的临时调试证书，仅上传 APK。

不同证书签名的 APK 不能直接覆盖已安装的应用。需要保留数据时，先在应用中导出备份；使用不同证书的自建版本需要卸载原应用后安装，再导入备份。拥有原签名文件的开发者可在本机配置相同签名以直接更新，签名文件不要提交到 Git。

SDK 脚本生成的调试密钥别名为 `androiddebugkey`，库密码和密钥密码均为标准调试密码 `android`。正式发布时请创建自己的发布签名并妥善保管。

## GitHub Actions

`.github/workflows/android-build.yml`在推送到`main` / `master`、提交Pull Request或手动运行时构建通用APK，执行语音策略检查、验证APK签名并上传产物。工作流自动还原源码中固定的压缩运行库，不把签名私钥上传到产物。[v1.1历史托管构建](https://github.com/dklk590/-/actions/runs/38160324722)已成功；它不能代替v1.2.0新依赖的构建验证。最新托管状态以[Actions记录](https://github.com/dklk590/-/actions)及对应提交为准。

交付APK使用官方SDK直接构建流程，具体版本、哈希、原生库、签名、对齐与资产一致性结果见`tests/build_validation.json`。此环境未运行Android真机或模拟器；JNI加载、设备音频输出、模型下载和系统权限需在Android设备确认。库打包对齐检查也不代替真实16KB页大小设备上的运行验证。
